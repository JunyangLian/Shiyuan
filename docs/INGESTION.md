# 首次建库与日常维护

拾源的核心产品原则：**第一次认真读完，之后一直自动维护。**

## 一、两种模式

### 首次建库 · Full Ingestion

- 完整读取全部授权目录，不设置每日文件数量硬上限。
- 所有支持的文档尽可能完整提取文字，进入全文索引和必要的向量索引。
- 所有符合条件的扫描 PDF、图片和 PPTX 内嵌图片进入 OCR 队列。
- 失败文件自动重试；达到重试上限后明确记录失败原因，不静默跳过。
- 任务持久化在本地数据库中，允许跨多个工作日运行，支持断点恢复和自动续跑。
- L0、L1、L2 都完成后，自动切换到日常增量维护。

### 日常维护 · Incremental Maintenance

- 新文件：自动解析和索引。
- 修改文件：只重新处理变化的内容版本。
- 移动文件：利用文件身份恢复既有资产关联。
- 删除文件：更新索引与引用状态，不保留失效正文。
- 查询发现知识缺口时，定向触发深度解析。

| 维度 | 首次建库 | 日常维护 |
| --- | --- | --- |
| 处理范围 | 全部授权资料 | 变化及需要修复的资料 |
| 文件数量限制 | 不设硬上限 | 按实际变化 |
| OCR | 全部符合条件的文件 | 新增或变化的文件 |
| 任务调度 | 以完成全量建库为目标 | 以低成本维护为目标 |
| 资源策略 | 可持续运行，按模式调速 | 尽量利用空闲资源 |

## 二、资源策略

不限制任务总量，不等于不限制计算资源。资源预算只控制处理速度和并发，不用于永久限制处理总量。

| 模式 | 目标 |
| --- | --- |
| 安静 | 优先保证电脑正常使用，后台低速处理全部资料 |
| 平衡（默认） | 正常使用与建库并行，按固定节奏处理 |
| 快速 | 尽可能利用 CPU、内存和磁盘资源，优先完成首次建库 |

即使选择安静模式，所有任务也会继续排队；暂停后队列和断点保留，继续或重启后会从断点接着处理。

## 三、三阶段完成标准

### L0：完整资产发现

所有授权目录中的文件都建立资产记录，包括路径、大小、类型、文件身份、指纹和状态。被排除的目录、文件和符号链接记录数量与原因。

### L1：完整文字理解

所有支持的文档完成文字提取、全文索引和必要的向量化。不能读取的文件明确记录原因。L1 完成的判断标准是：没有待解析版本，而不是“已经处理了一批”。

### L2：深度内容理解

对扫描 PDF、图片、PPTX 内嵌图片等进行 OCR、版面分析和必要的表格识别。不要把所有图片都直接交给视觉大模型；优先用本地 OCR 覆盖文字，复杂图表和无法识别的页面再按需使用视觉模型。

全文索引、向量索引和 OCR 都应有各自的完成状态；正文已提取不等于完全可检索。

## 四、Time to Full Coverage

**完整知识覆盖时间**：从用户首次授权数据源开始，到所有符合支持范围的文件完成规定解析和索引所需的时间。

除了总时间，还必须报告：

- L0、L1、L2 各自完成时间；
- 待解析、待 OCR、失败、不支持、被排除文件数量；
- 是否存在因为预算或暂停而尚未进入队列的文件。

不能通过跳过困难文件来缩短这个时间。

## 五、开发原则

1. 首次建库默认采用完整解析策略，不设置每日文件数量硬上限。
2. 所有授权且支持的文件都必须进入对应的处理队列；被盘点策略标为「仅登记」的类型除外。
3. 允许任务跨越多个工作日运行，支持断点恢复和自动续跑。
4. 资源预算只用于控制处理速度和并发，不用于永久限制处理总量。
5. 系统根据用户选择的资源策略处理；后续版本根据机器负载动态调整并发。
6. 对于损坏、加密、不支持的文件，必须明确记录状态和原因，不得静默跳过。
7. 首次建库完成后，自动切换到增量维护模式。
8. 用户可以暂停、恢复或调整资源策略，但不需要手动管理每个文件。

## 六、当前实现

- 数据源记录 `l0_completed_at`、`l1_completed_at`、`l2_completed_at`、`full_coverage_at`。
- 首次建库期间 L1/L2 使用无总量上限的持续队列；日常维护仍按每日预算限速。
- 扫描流程在首次建库时自动继续 L2 OCR；OCR 引擎不可用时记录事件并明确标记。
- 扫描任务记录 `files_skipped` 与 `skip_reasons`。
- `GET /api/stats` 返回 `ingest` 与 `full_coverage` 两个区块。
- `GET/PUT /api/settings/ingest` 提供资源策略与暂停/恢复。
- 核心启动时自动恢复所有尚未完成首次建库的数据源。
- 压缩包（ZIP/7Z/RAR）等非知识文件按盘点策略默认「仅登记」：只记录文件名、路径与大小，不解压；
  需要内容时可在盘点策略里把个别类型改为 `standard_parse`。解析结果页把这类文件标为「仅登记」，
  不计入「待解析」积压。
- 超过 64MB 的纯文本按前 8MB 头部采样解析，并在正文末尾标注「已截断」；PDF/PPTX 仍受 64MB 限制。
